## 行为与实现边界

| 输入 | 旧拒绝原因 | 本轮行为 |
| --- | --- | --- |
| `s054-0013` | Dialogue 171 的字面 Tab | 按 U+0020 收集字体需求，原始 Tab 保留 |
| `s057-0007` | Dialogue 566 的 DEL（U+007F） | 保留为字体字符，使用正常字体匹配、子集化及缺字策略 |
| `s045-0001` | 第 7 行的段结构诊断 | 屏蔽第一条段标题之前的前言，仅影响分析视图 |

libass 0.17.5 的 `ass_get_next_char` 将 Tab 返回为空格，但将 DEL 返回为 U+007F；
DEL 不在其 HarfBuzz 默认忽略字符表中，不能擅自丢弃。
结构样本实际以被注释的 `; [Script Info]` 开头；libass 能读取 520 个事件，
但不会把此前的 PlayRes、WrapStyle 等字段解释成有效 Script Info。
因此没有补造段标题，也没有改写原文。

实现位于 assfonts-ass：复用现有分析视图屏蔽方式，保留字节长度和行号。
任意段标题出现后即结束前言屏蔽，未知/畸形段和其他解析诊断仍然有效。
NUL、其他未验证控制字符及未知覆盖标签继续拒绝。

## TDD 与独立语义验证

覆盖字体切换后的 Tab、DEL 字符需求、无 Script Info 的前言、BOM/CRLF、
未知段/其他控制字符继续拒绝，以及原始字节保留。

临时探针从 vendored Open Sans 派生测试字体：Tab 映射到可见 B 字形，DEL 映射到可见 A 字形。
独立 libass 比较 6 对、36 个时刻：Tab 等价空格、DEL 等价对应字形、前言等价忽略均通过；
将 Tab 当字体字形、删除 DEL、把注释标题补成有效 Script Info 的三组负对照均产生差异。
随后这三种正例经过实际原生 CLI 与 WASM 的严格模式处理，输出字节相同，
完整字体与内嵌子集另比较 18 个时刻，零差异。

WASM 常规入口新增 Tab、前言和 DEL 变体：现在共 9 组、450 个时刻，独立渲染与缺附件负对照通过。
DEL 用例明确检查字符进入字体报告，使用 warn 策略后恢复原有严格测试策略；
原有 TTC/CFF/CP936 golden 未修改。

## 真实语料回归

固定同一新 WASM 产物、原始字体载入顺序和默认 warn 策略，重新处理全部 229 份：

- 146 份成功，83 份仍拒绝。
- 原有 143 份的字幕和 JSON 报告均逐字节不变；没有重复运行其上一轮百万采样渲染。
- 新增 3 份全部成功，146 份成功输出移除新增 Fonts 段后均与原输入逐字节相同。
- 其余 83 份仍在相同首个错误处拒绝，没有扩大未知语法容错；输入 SHA-256 全部核对。

新增三份按原始完整字体与 WASM 子集独立渲染，libass 0.17.5、1920×1080、
系统 provider NONE、两侧固定 Noto Sans SC 默认字体：

| 输入 | 采样时刻 | 不同帧 |
| --- | ---: | ---: |
| `s045-0001` | 3,860 | 0 |
| `s054-0013` | 11,209 | 0 |
| `s057-0007` | 3,585 | 0 |
| 总计 | 18,654 | 0 |

双方均无严重渲染错误。但 `s057-0007` 的 DFPJinWenW3-B5 候选仍缺 U+007F、吗、话，
报告正常保留 missing_cmap_glyphs warning；双方都有相同的 1,050 条 U+007F 回退失败日志。
这是默认 warn 策略下的成功，不是字体覆盖完整，也不保证其他默认字体环境的渲染结果。

原生工作区测试、clippy（所有 targets、拒绝 warning）、fmt、release 构建、

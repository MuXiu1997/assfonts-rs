## 完整字体基准

- A 使用未子集化的预处理 ASS 和该案例原始字体目录的完整字体文件清单，独立于 Rust 处理报告选出的字体列表；B 仅加载 Rust ASS 附件。
- 同一 libass 0.17.5，独立 Library/Renderer/Track，系统字体 provider 为 NONE，且构建禁用 CoreText/Fontconfig/DirectWrite。
- 模拟 1920×1080、方形像素播放，保留 ASS 原有 PlayRes/LayoutRes。
- 共 21982 条 Dialogue，其中 21646 条正时长、1817 条含动态标签。采样事件起止前后 1ms、中点，动态事件增加 100ms 间隔和多个比例点。
- 143445 个采样点、102945 个非空点，全部 ASS_Image 链顺序、位置、尺寸、颜色和逐行位图精确一致，无需误差容限；相同合成器输出的 RGBA 像素必然一致。
- 无字体加载失败；仅两份虫师在双方日志中都有同一个隶书 glyph 0x0 警告，来自只有覆盖标签而无文字/绘图的空 staff 事件，与此前审计一致。
- 3 个真实样本无字体负对照均有可见差异，分别为 21270、86581、6042 像素。

固定竖排样例另以 1280×360 渲染四个时刻：完整字体与 Rust 附件均为零差异；无字体和单字体负对照均符合预期。另在 1080p 下错误移除输出的 `@`，500ms 帧出现 17445 个差异像素，证明样例能检测竖排语义丢失。

这是固定渲染环境下的采样验证，不是所有时间、分辨率或播放器均等价的证明。
